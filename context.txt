# Project Context

## What this project is

**Technical Interview Reasoning Analyzer** — a tool that analyzes technical interview interactions and eventually evaluates reasoning quality, evidence, and interview performance.

The project is being built incrementally. The current focus is establishing the frontend and backend foundation before implementing the actual analysis engines.

---

## Tech Stack

### Backend

* Python
* FastAPI
* Uvicorn
* Pydantic Settings
* SQLAlchemy
* psycopg
* Alembic
* PostgreSQL
* Ruff

### Frontend

* React
* TypeScript
* Vite
* React Router

### Current infrastructure

* Backend: `http://127.0.0.1:8000`
* Frontend: `http://localhost:5173`
* Backend Python virtual environment: `backend/venv/`

## Important decisions

* Backend and frontend are separate applications.
* Backend uses FastAPI.
* Frontend uses React + TypeScript + Vite.
* React Router is used for frontend routing.
* Backend API communication is centralized in `frontend/src/services/`.
* Backend configuration is centralized in `backend/app/core/config.py`.
* Backend API routes are separated from `main.py`.
* Ruff is used for Python linting and formatting.
* The Python virtual environment for the backend is specifically `backend/venv/`.
* Frontend does not use the Python virtual environment.
* We are intentionally avoiding premature infrastructure and only adding technologies when the project needs them.
* PostgreSQL is the database for interview/session persistence.
* Database access lives in `repositories/`; business logic lives in `services/`.
* Alembic is used for schema changes; the app does not call `create_all()` on startup.
* Final UI design has not been implemented yet.
* Speech analysis, code analysis, LLM integration, evidence, and reporting are not implemented yet.
* Database tables are created with Alembic migrations, not application startup.
* Interview lifecycle is `CREATED` -> `IN_PROGRESS` -> `COMPLETED`. Invalid transitions return HTTP 409.
* Default PostgreSQL database name is `interview_analyser`.
* Alembic must be run from the `backend/` directory.

## Important gotchas

* Use `backend/venv/` for the Python backend environment.
* Do not create another Python virtual environment unless there is a specific reason.
* When working on React, the Python venv is irrelevant.
* Backend runs on port `8000`.
* Frontend runs on port `5173`.
* FastAPI root `/` currently returns `404`; this is expected because the implemented endpoint is `/health`.
* FastAPI health endpoint: `http://127.0.0.1:8000/health`
* FastAPI documentation: `http://127.0.0.1:8000/docs`
* Interview API base path: `http://127.0.0.1:8000/api/v1/interviews`
* PostgreSQL must be running before interview endpoints or Alembic migrations will work.
* Create the `interview_analyser` database before running migrations.
* Run Alembic from `backend/`: `alembic upgrade head`
* Do not push `.env` files to GitHub.
* Do not rename existing project folders/files without updating this document.
* Do not introduce duplicate folder names such as another `backend`, `frontend`, or another virtual environment.
* Before adding a new library/framework, check whether it is actually required by the next feature.

## Development workflow

For backend:

```powershell
cd backend
.\venv\Scripts\Activate.ps1
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

For database migrations:

```powershell
cd backend
.\venv\Scripts\Activate.ps1
alembic upgrade head
```

For backend code quality:

```powershell
ruff format .
ruff check . --fix
ruff check .
```

For frontend:

```powershell
cd frontend
npm run dev
```

For frontend production build:

```powershell
npm run build
```

After completing a meaningful project step:

```powershell
git add .
git commit -m "Description of completed step"
git push
```
